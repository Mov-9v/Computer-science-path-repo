# Problem Specification: Cascading Duration Decomposition & Telemetry Packet Decoder Engine

## 1. Problem Specification and System Architecture

In mission-critical embedded telemetry and industrial IoT architectures, raw packets dispatched from remote sensor stations consist of packed hardware measurements, digital sensor counts, operation flags, and high-magnitude timestamps. A robust software engine must translate these discrete data streams into calibrated, human-auditable engineering metrics without falling prey to silent truncation, overflow, or data corruption.

### 1.1 Problem Statement and Hardware Operational Context

A remote environmental monitoring unit acquires three physical sensor readings during each sampling frame:

1. **Epoch Timestamp:** A high-magnitude elapsed timestamp representing total operational seconds recorded since the base system epoch.
2. **Raw ADC Measurement:** An unsigned digital integer generated by an Analog-to-Digital Converter (ADC) operating within the hardware range of $0$ to $4095$.
3. **Hardware Mode Flag:** A single character designator (`'C'` for Calibrated, `'U'` for Uncalibrated, `'D'` for Diagnostic) establishing the operating regime.

The processing subsystem must ingest these values, compute precise mathematical and temporal transformations, and output an uncorrupted hardware telemetry summary report.

### 1.2 Mathematical and Algorithmic Specifications

The computation engine is strictly bound by the following physical and mathematical definitions:

* **Hardware Calibration Constants:**
  * Base Calibration Scale Factor: $k = 0.080566$
  * Zero-Point Baseline Offset: $T_0 = 15.25\text{ }^\circ\text{C}$
  * Maximum ADC Full-Scale Resolution: $\text{ADC}_{\max} = 4095$
* **Calibrated Sensor Temperature ($T_c$):**
  $$T_c = (\text{rawADC} \times k) - T_0$$
* **Sensor Saturation Ratio ($P_{\text{sat}}$):**
  $$P_{\text{sat}} = \left(\frac{\text{rawADC}}{\text{ADC}_{\max}}\right) \times 100$$
  *Defensive Casting Mandate:* Because raw digital measurements and resolution bounds are represented as discrete integers, calculating this metric without explicit floating-point promotion introduces silent truncation ($2845 / 4095 = 0$). An explicit `static_cast<double>` conversion is mandatory.
* **Hierarchical Cascading Duration Decomposition:**
  The elapsed operational time must be broken down sequentially using integer division (`/`) and modulo reduction (`%=`) into hierarchical units without data loss:
  * Days ($1\text{ Day} = 86400\text{ Seconds}$)
  * Hours ($1\text{ Hour} = 3600\text{ Seconds}$)
  * Minutes ($1\text{ Minute} = 60\text{ Seconds}$)
  * Residual Seconds
* **ASCII Collating Sequence and Offset:**
  Using character arithmetic, the character mode flag must be decoded to yield its raw decimal ASCII value and its zero-based position relative to the English uppercase alphabet baseline `'A'`:
  $$\text{Offset} = \text{modeChar} - \text{'A'}$$
* **Atomic Packet Counter Sequence:**
  Demonstrate the semantic distinction of post-increment (`var++`) by logging a transaction packet identifier ($100$), outputting the initial value during evaluation, and confirming that the underlying memory location was modified to $101$.
